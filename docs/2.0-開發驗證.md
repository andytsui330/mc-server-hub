## 真正 Tauri 視窗的自動操作

需要已安裝的 JDK，以及可使用的 Playwright；本測試不安裝任何工具。`MCHUB_PLAYWRIGHT` 可指到既有 Playwright 套件的絕對路徑，未指定時用 Node 的正常套件解析。

先在 `app/` 執行 `npx tauri build --no-bundle`，再回 repo 根目錄：

```powershell
$env:MCHUB_DATA_DIR = Join-Path $env:TEMP ('mchub-ui-' + [guid]::NewGuid().ToString('N'))
# 使用 Codex 既有 bundled runtime 時，將下一行改成當場查得的套件絕對路徑：
# $env:MCHUB_PLAYWRIGHT = '...\node_modules\playwright'
node tests/ui.cjs
node tests/assets.cjs
```

腳本拒絕已存在或 TEMP 外的資料夾。它自行編譯 `legacy/tests/FakeServer.java`、分配空連接埠，透過真正 WebView2 點選畫面，不使用假的 API 回覆。WebView2 個人資料也放在同一個測試資料夾。需要改 CDP 埠時設定 `MCHUB_CDP_PORT`，預設 9229。

## 第 6 步：兩版對等的重跑方法

兩版都用現有 `FakeServer.java`、`FakeInstaller.java`；後者同時支援假 Forge／NeoForge。以下都是 Windows 測試；Mac 的真實開機、⌘K、原生選夾／拖放留到計畫第 12 步。

```powershell
node tests/ui-parity.cjs
```

`MCHUB_PLAYWRIGHT` 同上；舊版畫面使用電腦既有的 Edge（headless），不另下載瀏覽器。UI 對照預設隨機分配 CDP 埠；指定 `MCHUB_CDP_PORT` 時先確認空埠，連線後必須再核對唯一伺服器 ID 與本輪 TEMP 路徑。未通過就拒絕操作，清理時也再次核對。自測涵蓋錯誤 ID、真路徑、空清單與額外伺服器；拿掉保護的負向副本確實紅燈，正式版本綠燈。

剪貼簿測試**預設跳過**。只有使用者當次同意覆寫現有剪貼簿後，才在該命令的子程序設 `MCHUB_TEST_CLIPBOARD=1`。測試先寫固定測試字串，再複製地址、種子及加入說明讀回；不讀原剪貼簿、不宣稱能還原圖片／檔案，失敗訊息也不保存剪貼簿原文。Windows 貼上換行以 CRLF／LF 等價比對。

`create_parity.rs` 直接編譯正式 `create.rs`、`hub.rs`、`settings.rs`，只將網路回應改由測試資料供應；正式產品不引用此入口，也沒增加測試開關或放寬下載白名單。假 jar、安裝器、SHA-1／SHA-256 與回應清單由 Python 同時交給兩版。正式下載的串流核對、安裝器子程序、工作進度、寫檔、登記與第一次開機仍實際執行。這能證明**離線工作流程對等**，不代表連過官方 CDN 或跑過真的 Forge／NeoForge 安裝器。
